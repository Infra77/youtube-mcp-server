# ADR-0010: completion-audit remediation

Date: 2026-11-02. Status: implemented locally; independent human review pending.
Research: [[Google OAuth Desktop PKCE]], [[Quota Buckets and Reservation]], [[Playlist Approval Invariants]], [[CI Fixture Isolation]], [[Postgres Crash Recovery]].

Credential generation is pinned to encrypted-file SHA-256 per running vault; replacing/deleting a credential invalidates access before cached-token reuse. Reauthorization requires restarting MCP. Account and access token may not drift across credential generations. Logout removes local credentials even if Google revocation fails and reports both outcomes separately. Orphan-account local deletion requires a typed human channel-ID confirmation.

Metadata caching is bounded to 128 entries for five minutes, in process and keyed by account plus exact method/query. Personal collection responses are never cached. Authentication is checked before a hit. Preflight conservatively reserves cache-miss worst-case cost; hits charge no API cost and unused capacity is released. A cached request may still be rejected when the worst-case workflow budget is unavailable; this deliberately prioritizes a simple safe preflight.

Personal collections traverse up to two pages within unchanged item caps. Their maximum read budget is 21 general read units; recommendations add one search and one hydration (22 reads). Repeated next-page tokens fail closed. Private/inaccessible collection errors stop the workflow with a typed error rather than falsely claiming complete data.

New proposal schema 2 persists exclusion reasons and canonical URLs. Old raw proposal hashes remain checked against stored bytes; no existing migration is rewritten. Commit outputs label proposed versus confirmed counts and enumerate per-video status.

Fresh console-only REPAIR authorization can repair PARTIAL with a known playlist: atomically claim, verify identity, read remote order, require an exact prefix of the approved ordered IDs, insert only missing suffix, read back. Unknown playlist creation is never retried automatically. RESOLVE records human reconciliation without pretending remote success. Operators must stop other writers before recovery; in-progress CREATING/REPAIRING cannot be repaired directly.

Retention deletes all drafts/grants/journals older than seven days, including unresolved attempts, plus expired uncommitted drafts, and old quota ledger rows. Startup/hourly cleanup and explicit cleanup use the same code. An unresolved write must be inspected before that deadline; losing local evidence is not authorization to retry. No personal remote content is retained in application evidence. Offline installations must run cleanup before reuse; deletion requests use immediate local commands.

Dependency upgrades retain Boot 3.5 / Spring AI 1.1 compatibility. The OSV HTTP-only MCP advisory is recorded as not applicable to the stdio-only transport, never globally suppressed. Human review must confirm this and every other security disposition before final release.
